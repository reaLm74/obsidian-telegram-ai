# 🗺️ Дорожная карта: Obsidian Telegram AI — 2 года (Q3 2026 → Q2 2028)

> Горизонт: **август 2026 — июль 2028**. Документ заменяет полугодовой [Roadmap.md](Roadmap.md)
> — его содержимое поглощено кварталами Q3–Q4 2026 и уточнено по фактическому состоянию кода.

## Точка отсчёта (август 2026)

| Параметр | Факт |
|----------|------|
| Версия | 0.2.0 |
| Кодовая база | ~15 000 строк TS, `strict: true`, 20 тестовых файлов |
| AI-провайдеры | OpenAI (прод), Claude + Gemini (в работе, не в релизе) |
| Платформы | Desktop only (`isDesktopOnly: true`) |
| Дистрибуция | Только GitHub Releases, в Community Registry **не опубликован** |
| CI | Только релизные workflow; **нет прогона lint/tsc/тестов на PR** |
| Локализация | EN, RU |
| Документы | PDF, DOCX, TXT, CSV, код (локально) |

## Три продуктовые ставки на два года

1. **Приватность как фича.** Универсальный слой провайдеров → OpenAI-совместимый endpoint → локальные модели (Ollama / LM Studio). У пользователя должна быть возможность не отправить наружу ни байта.
2. **Дистрибуция и мобильность.** Публикация в Community Registry и снятие `isDesktopOnly` — два рычага, которые кратно меняют размер аудитории. Всё остальное — работа с уже пришедшими.
3. **От «инбокса» к «памяти».** Сегодня плагин — труба «сообщение → заметка». За два года — семантический слой: дедупликация, связи, поиск по хранилищу, дайджесты, ответы бота из вашего же vault.

# Год 1 — «Взросление продукта»

## 🟢 Q3 2026 (авг–окт) → v0.3 «Три провайдера и зелёный CI»

**Тема:** довести до релиза то, что уже наполовину написано, и закрыть дыру в процессе.

### AI-провайдеры
- [ ] Единый интерфейс `AIProvider`: `process()`, `processWithVision()`, `transcribe()`, `testKey()` — вместо трёх ad-hoc модулей `openai.ts` / `claude.ts` / `gemini.ts`
- [ ] Claude: Vision (base64 image block), актуальные модели, `anthropic-beta` headers
- [ ] Gemini: Vision (`inlineData`), Safety Settings, актуальные модели
- [ ] Общий `aiRetryWrapper` с уважением `Retry-After` из 429 и реальным подключением `aiTimeout` к HTTP-запросам
- [ ] `modelCapabilities.ts` как единый источник правды о vision/контексте/цене; предупреждение в UI при выборе модели без vision
- [ ] Кнопка «Проверить ключ» для всех провайдеров + внятные ошибки квоты и отозванного ключа

### Процесс и гигиена репозитория
- [ ] Workflow `ci.yml`: `tsc --noEmit` + `eslint` + `vitest run --coverage` на каждый PR в `develop` (блокирующий)
- [ ] Dependabot + CodeQL
- [ ] Чистка корня: `eslint-report.json`, `eslint-output.txt`, `out-test*.js`, `coverage/`, `tmp/`, `analyze_eslint.py` → в `.gitignore` или в `scripts/`
- [ ] Сборка `main.js` только в CI, не в коммитах
- [ ] Закрыть накопленный техдолг: незакрытые `TODO` в `clientMessageToBotMessage.ts` (потеря полей при конвертации), `handlers.ts:367` (лимит размера файла)

**Критерий выхода:** релиз 0.3 собран из зелёного CI; три провайдера с vision; ни один PR не мержится без тестов.

## 🔵 Q4 2026 (ноя–дек) → v0.4 «Ничего не теряется»

**Тема:** доверие. Заметка должна появиться ровно один раз и никогда не пропасть.

### Надёжность доставки
- [ ] Персистентная очередь необработанных сообщений — переживает перезапуск Obsidian и падение AI-запроса
- [ ] Идемпотентность: дедупликация по `message_id` + `chat_id` в frontmatter, exactly-once создание заметки
- [ ] Экспоненциальный backoff и «карантин» для сообщений, упавших N раз, с ручным ретраем из истории обработки
- [ ] Пул AI-запросов (лимит 3–5 одновременных), debounce `saveSettings()`
- [ ] Бюджеты производительности: `onload` < 500 мс, обработка текста < 2 с, ленивая загрузка неиспользуемых провайдеров

### Контент
- [ ] `.xlsx` (JSZip + XML), `.pptx`, `.epub`
- [ ] OCR изображений через Vision с отдельным промптом
- [ ] `edited_message` → обновление существующей заметки по `messageId`; опциональная история правок
- [ ] Реакции и ответы (`reply_to_message`) → связи между заметками

**Критерий выхода:** сутки офлайна и 500 сообщений подряд не приводят ни к одному потерянному или задвоенному файлу.

## 🔒 Q1 2027 (янв–мар) → v0.5 «Безопасность и витрина»

**Тема:** пройти ревью Obsidian и не быть страшным для пользователя с чужими ключами.

### Безопасность
- [ ] Шифрование **всех** секретов в `data.json` (сейчас гарантированно только bot token), опциональный мастер-пароль на старте
- [ ] Зачистка ключей из памяти после использования; запрет попадания секретов в логи и в историю обработки
- [ ] Валидация всех входящих данных Telegram API (schema-guard на границе)
- [ ] Rate limiting и защита от флуда внутри whitelisted-чата
- [ ] Privacy Mode: полное отключение сети кроме Telegram
- [ ] Аудит зависимостей (`telegram`/GramJS, `pdf-parse`, `mammoth`) + план замены хрупких

### Публикация
- [ ] Приведение к Obsidian Plugin Guidelines: CSP, отсутствие динамического кода, корректный `onunload`, никаких утечек интервалов
- [ ] PR в `obsidianmd/obsidian-releases`, прохождение ревью
- [ ] Страница плагина, скриншоты, демо-GIF, README без «install manually»

**Критерий выхода:** плагин в Community Registry; SECURITY.md описывает реальность, а не намерения.

## 📱 Q2 2027 (апр–июн) → v0.6 «Mobile beta»

**Тема:** снять `isDesktopOnly`. Самый тяжёлый эпик карты — отдельный трек, а не «фикс несовместимостей».

- [ ] Заменить `node-telegram-bot-api` на собственный fetch-клиент Bot API без Node-специфики (`fs`, `http`, `Buffer`)
- [ ] Абстракция файловой системы: всё через `Vault.adapter`, ни одного `require("fs")` в рантайме
- [ ] Замена `node-machine-id` и Node-`crypto` на WebCrypto
- [ ] Изоляция GramJS (user-режим) в desktop-only модуль с ленивой загрузкой — мобильная сборка его не тянет
- [ ] Локальное извлечение документов: проверка `pdf-parse`/`mammoth` на мобиле, деградация вместо падения
- [ ] Touch-UI для модалок; экономия батареи (интервалы polling, пауза при неактивном приложении)
- [ ] Матрица тестирования: Windows / macOS / Linux / iOS / Android

**Критерий выхода:** beta-сборка работает на iOS и Android в bot-режиме; desktop-функциональность не деградировала.

# Год 2 — «От инбокса к памяти»

## 🚀 Q3 2027 (июл–сен) → v0.7 «Mobile GA + Telegram Business»

- [ ] Снятие `isDesktopOnly` в манифесте, mobile GA
- [ ] **Telegram Business connection** как легальная альтернатива MTProto-логину: бот, подключённый к Business-аккаунту, получает сообщения без `api_id`/`api_hash` — убирает самый сложный шаг онбординга
- [ ] Форумы/топики, каналы и комментарии как источники
- [ ] Меню команд бота: `/status`, `/retry`, `/category`, `/search`
- [ ] Custom AI Provider: любой OpenAI-совместимый endpoint (OpenRouter, Groq, self-hosted)

## 🏛 Q4 2027 (окт–дек) → v1.0 «Стабильность»

- [ ] Заморозка формата `data.json` и правил миграции; обратная совместимость в пределах 1.x
- [ ] Публичный Plugin API: события `message-processed`, `note-created`, регистрация собственных пост-процессоров
- [ ] Интеграции: Dataview (frontmatter-контракт), Tasks (извлечение TODO), Templater
- [ ] Локализация: DE, ES, ZH + crowdsourced-перевод через GitHub
- [ ] Документация 1.0: видео Quick Start, FAQ, Troubleshooting, Contributing guide
- [ ] Покрытие тестами ≥ 80 % по критическим модулям, e2e-прогон на реальном тестовом боте в CI

**Критерий выхода:** 1.0 — то, что не стыдно рекомендовать как основной инструмент; апгрейд с 0.x без ручных действий.

## 🧠 Q1 2028 (янв–мар) → v1.5 «Локальные модели и смысл»

- [ ] Ollama / LM Studio как first-class провайдер: автоопределение запущенного сервера, список моделей, нулевая сетевая утечка
- [ ] Локальная транскрипция (whisper.cpp) как альтернатива Whisper API
- [ ] Эмбеддинги (локальные или API) + векторный индекс в vault
- [ ] Семантическая дедупликация: «похоже, ты уже сохранял это» вместо ещё одной заметки
- [ ] Автосвязывание: новые заметки линкуются к существующим по смыслу, а не по совпадению слов
- [ ] Категоризация 2.0: мультикатегорийность, иерархия, feedback loop (перенёс заметку → классификатор учится), кэш в frontmatter

## 🔄 Q2 2028 (апр–июн) → v2.0 «Двусторонний контур»

- [ ] Obsidian → Telegram: отправка заметки, выделенного фрагмента, ежедневного/недельного дайджеста
- [ ] Бот отвечает из вашего vault: вопрос в чат → RAG-ответ по хранилищу со ссылками на заметки
- [ ] Напоминания и отложенные задачи из сообщений
- [ ] Мультиаккаунтность: несколько ботов/аккаунтов → разные хранилища или папки
- [ ] Командный режим: общий чат → общий vault с атрибуцией автора

**Критерий выхода:** Telegram перестаёт быть только входом и становится интерфейсом к знаниям.

## Сквозные треки (идут все 8 кварталов)

| Трек | Правило |
|------|---------|
| **Качество** | Каждая фича приезжает с тестами; покрытие не падает — CI блокирует |
| **Безопасность** | Любая новая точка исхода данных попадает в таблицу «что уходит наружу» в README до мержа |
| **Производительность** | Бюджеты `onload` и обработки проверяются на каждом минорном релизе |
| **Комьюнити** | Ответ на issue ≤ 72 ч; changelog на RU и EN; анонсы в [канале](https://t.me/Obsidian_Telegram_AI) |
| **Документация** | Фича без документа в `docs/` считается незавершённой ([Release Checklist](Release%20Checklist.md)) |

## Приоритеты (MoSCoW на 2 года)

| Приоритет | Что |
|-----------|-----|
| **Must** | Мультипровайдерность, CI-гейт на PR, надёжная доставка, шифрование всех ключей, Community Registry, mobile |
| **Should** | Новые форматы, sync правок, Telegram Business, Plugin API, локальные модели |
| **Could** | Семантический поиск, RAG-ответы, дайджесты, командный режим, мультиаккаунтность |
| **Won't** | Webhook-режим (нужен публичный хост), E2E-шифрование хранилища, платная версия и облачный бэкенд |
