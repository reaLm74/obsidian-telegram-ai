1. **Приватность как фича.** Универсальный слой провайдеров → OpenAI-совместимый endpoint → локальные модели (Ollama / LM Studio). У пользователя должна быть возможность не отправить наружу ни байта.
2. **Дистрибуция и мобильность.** Публикация в Community Registry и снятие `isDesktopOnly` — два рычага, которые кратно меняют размер аудитории. Всё остальное — работа с уже пришедшими.
3. **От «инбокса» к «памяти».** Сегодня плагин — труба «сообщение → заметка». За два года — семантический слой: дедупликация, связи, поиск по хранилищу, дайджесты, ответы бота из вашего же vault.

**Тема:** довести до релиза то, что уже наполовину написано, и закрыть дыру в процессе.

- [x] Gemini: Vision (`inlineData`), Safety Settings в настройках, актуальные модели (3.7 / 3.6 Flash, 3.1 Pro, 3.5 Flash-Lite), нативная транскрипция аудио, ключ переехал из query-строки в заголовок
- [x] Один `withAIRetry` (`src/ai/retry.ts`) вместо трёх копий retry/backoff; `Retry-After` уважается, ожидание дольше 60 с не блокирует очередь

- [x] Кнопка «Проверить ключ» для всех провайдеров + различение неверного ключа, пустого баланса, rate limit и недоступной модели
- [x] Claude и Gemini помечены как beta в списке провайдеров и в модалке: они впервые едут в релиз и прошли несравнимо меньше реального трафика, чем OpenAI

**Сверх плана.** Линейка GPT-5.6 (`gpt-5.6-sol` / `-terra` / `-luna`) несовместима с 4.x на
уровне запроса: `max_completion_tokens` вместо `max_tokens` и отказ от `temperature` (то же
самое — у o-серии и семейства Claude 5). Плагин выбирает форму запроса по id модели, включая
неизвестные ему `gpt-5.*`, а слайдер температуры прячется там, где модель её не принимает.

Оттуда же выросли ещё два пункта, которых в плане не было:

- **Бюджет рассуждений — у OpenAI и Claude.** Reasoning-токены вычитаются из лимита ответа
  и пишутся раньше него, поэтому модель с дефолтным уровнем успевает израсходовать весь
  лимит в 2000 токенов и вернуть пустоту. Плагин просит минимальный уровень, который
  принимает конкретная модель (`none` у GPT-5.6, `minimal` у GPT-5, `low` у o-серии и у
  Claude), а пустой ответ с `finish_reason: length` / `stop_reason: max_tokens` объясняется
  как исчерпанный бюджет. У Claude это `output_config.effort`; устаревший `budget_tokens` не
  отправляется никогда — модели 4.7+ отвечают на него 400. Claude Haiku 4.5 параметр не
  принимает вовсе, ему не отправляется ничего. У Gemini размышления бюджетируются отдельно
  от `maxOutputTokens`, поэтому там это только вопрос цены — уровни занесены в таблицу,
  управление отложено (документация противоречит себе в форме параметра).
- **Даты отключения.** Модели с объявленной датой выключения (GPT-4, GPT-4 Turbo, GPT-3.5
  Turbo, o-серия, исходная линейка GPT-5) убраны из выпадающего списка, но остались в
  таблице: уже выбранная модель продолжает работать и получает предупреждение с датой.

## 🔒 Q1 2027 (янв–мар) → v0.5 «Безопасность и витрина»

**Тема:** пройти ревью Obsidian и не быть страшным для пользователя с чужими ключами.

### Безопасность

- [x] Шифрование **всех** секретов в `data.json`: единый `src/utils/secretStore.ts` вместо пяти копий логики — `botToken`, `openAIApiKey`, `claudeApiKey`, `geminiApiKey`, `telegramApiHash`. Старые значения в открытом виде дошифровываются при загрузке
- [x] **Уточнение по сессии GramJS:** её нет в `data.json`. `StoreSession` хранит ключ авторизации в `localStorage` Electron — то есть он **не** уезжает с синхронизацией хранилища (предпосылка в старой редакции карты была неверна), но и пином не защищён и читается любым, у кого есть доступ к профилю Obsidian. Зафиксировано как есть в `SECURITY.md`; шифрование потребовало бы собственного класса сессии — отдельная задача, не «дописать ключ в список»
- [x] Сценарии пин-кода: смена пина с перешифровкой всех секретов и осознанный сброс при забытом (модалка перечисляет, что будет очищено и где это взять заново; заметки не трогаются). Проверка пина — по отдельному верификатору, а не по бот-токену
- [x] Секреты не попадают в логи, чат, историю обработки, журнал доставки и диагностический отчёт (`src/utils/secretRedaction.ts`). Причина конкретная: Bot API отдаёт файловые URL вида `.../bot<TOKEN>/...`, а текст ошибки уходит ответом в Telegram-чат
- [x] Валидация входящих данных Telegram на границе (`messageGuard.ts`): форма проверяется до первого разыменования, включая `date`, из которого раньше могла получиться Invalid Date в имени файла
